## Deliverables
1. Pin compatible ASP.NET Core Identity and EF Core SQL Server packages centrally.
2. Add Guid-based `ApplicationUser` and `ApplicationDbContext` containing Identity tables only.
3. Register SQL Server DbContext, Identity stores/roles/token providers and application cookie.
4. Implement the HTTP claims adapter for `ICurrentUser` in API and register authentication order.
5. Add a development SQL Express connection without credentials in source.
6. Generate and apply the first Identity migration to local SQL Express and inspect its schema.
7. Update decisions, design documents, evidence, state, handoff and validator.

## Step acceptance
SA01: Domain/Application remain persistence- and ASP.NET-transport-independent.
SA02: Identity uses Guid keys and the four existing role names; this step does not seed accounts.
SA03: application cookie is HttpOnly, SameSite Lax, Secure in production and has no token in JS.
SA04: email confirmation is required by Identity configuration; endpoints remain absent.
SA05: migration creates Identity schema only and applies successfully to local SQL Express.
SA06: restore/build/validator pass with zero warnings/errors; `/healthz` stays public and healthy.
SA07: no Customer auto-link, Q07 rule, business endpoint, frontend edit or automated test is added.
