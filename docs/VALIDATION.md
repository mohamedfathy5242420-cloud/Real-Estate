# أربع طبقات للتحقق

تعريف مقترح للمشروع وليس نقلًا حرفيًا لتعريفات لم تظهر في الشات المرجعي.

| الطبقة | تجهيز الوثائق | تنفيذ التطبيق لاحقًا |
| --- | --- | --- |
| L1 Structure | وجود الملفات ومراجع الخطوة والحالة | build والاعتماديات والتحليل |
| L2 Rules | مطابقة القرارات وقواعد العمل للحوار | Unit tests للقواعد والانتقالات |
| L3 Integration | اتساق الخطة والقوالب والتسليم | قاعدة البيانات والقيود والصلاحيات والرسائل |
| L4 Acceptance | جلسة جديدة تفهم المطلوب وحدود العمل | رحلة عميل/موظف كاملة وحالات الفشل |

## الأدلة
evidence.md يسجل معيار القبول والطبقة والفحص والأمر والنتيجة والمراجع والحدود.
النتائج: Passed / Failed / Not run / N/A مع السبب.
الفحص اليدوي موسوم يدويًا، ولا يعد اختبار تطبيق.
سكريبت الملفات لا يثبت صحة Business ولا يحول المراجعات اليدوية لنجاح تلقائي.

## السكريبتات
validate.ps1 الآن يفحص وثائق العمل ويخرج nonzero عند الخلل.
يفحص أيضًا تعريفات BR/UC/AC وتغطيتها في TRACEABILITY ومراجع الخطوة النشطة والمراحل والأسئلة.
هذه تغطية ربط وثائق فقط وليست برهانًا على اكتمال الاختبارات أو تنفيذ السلوك.
سكريبتات build/tests والتكامل تضاف مع وجود تطبيق واختبارات حقيقية.
لا نضيف فحوصًا شكلية لا تختبر سلوكًا.

## أمثلة اختبارات لاحقة
منع ظهور الملاحظات للعميل، إسناد الطلب لنفس الموظف، إلغاء الموعد عند إعادة الجدولة،
عدم تأكيد الحجز دون رد المطور، عدم إتاحة الوحدة تلقائيًا بانتهاء الحجز، وعدم تكرار أثر الرسالة.
