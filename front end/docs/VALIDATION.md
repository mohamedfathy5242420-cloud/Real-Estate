# أربع طبقات — Angular frontend
نفس نظام التحقق العام مع تكييف الواجهة، لا نقل حرفي لتعريفات المصدر.

| الطبقة | الآن: Workflow | لاحقًا: Angular |
| --- | --- | --- |
| L1 Structure | ملفات ومراجع وحالة متسقة | build وtype checking والتحليل |
| L2 Rules | مراجعة قواعد Business وتجربة الحالات | اختبارات مكونات وخدمات ونماذج |
| L3 Integration | اتساق العقود والتسليم والمراحل | HTTP adapters والتوجيه والجلسة مع العقود والخادم |
| L4 Acceptance | تجربة تسليم جلسة جديدة | رحلات المتصفح والموبايل ولوحة المفاتيح؛ English LTR أولًا حسب FE-D007، وRTL عند دعم العربية لاحقًا |

لكل شاشة: loading / empty / error / success، وforbidden/expired/conflict عند الحاجة.
للتحقق البصري لاحقًا: المقاسات المختبرة، خطوات التجربة ولقطات فعلية عند الحاجة.
لا تكفي لقطة شاشة لإثبات الصلاحيات أو نجاح حفظ البيانات.

الأدلة: AC والطبقة والأمر والنتيجة والبيئة والمراجع والحدود.
النتائج Passed / Failed / Not run / N/A مع السبب.
المراجعات اليدوية موسومة بذلك؛ mocks لا تعد تكاملًا مع Backend.
سكريبت الوثائق الحالي لا يثبت نجاح Angular build أو اختبار متصفح.
التحقق الموسع يفحص BR/UC/SC/FAC ومراحل F وتغطية الخريطة ومراجع الخطوة.
يقارن نسخ shared بمصادرها عند توفرها. غياب المصدر يعني Not verified للمزامنة؛ اختلافه يفشل الفحص.
