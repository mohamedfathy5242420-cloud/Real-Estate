# F01-S04 — عقد التكامل المقترح مع Backend
Status: Proposed design contract — no implemented or Backend-approved HTTP endpoint.
كل عملية مستقبلية تربط UC وBR والشاشة SC وسيناريو FAC من docs/business/TRACEABILITY.json.
Shared use cases describe domain operations, not implemented endpoints. Screen API needs remain proposed until a real contract is agreed.
لا API فعلي أو endpoints مؤكدة في هذه المرحلة.
قرارات D015–D030 معتمدة في Business، لكن أسماء الحقول وطرق HTTP وتنسيق الأخطاء لم تُعتمد بعد.

قبل تنفيذ أي رحلة نتفق على:
- العملية والـroute والـmethod وإصدار العقد.
- الطلب والرد والحقول المطلوبة/الاختيارية وقواعد validation.
- authentication والroles وملكية المورد.
- حالات النجاح والخطأ ورمز الخطأ ورسالة العرض.
- pagination/filter/sort، وتنسيق الوقت والمنطقة الزمنية والعملات.
- تعارض التوفر وتكرار الطلب وتحديث الحالة من الخادم.
- للمعاينات: بداية مقترحة خلال 30 يومًا، مدة افتراضية 60 دقيقة، بداية ونهاية نهائيتان
  يثبتهما الموظف؛ UTC في التخزين والتوقيت المناسب في العرض. رد الخادم يميز انتهاء pending،
  تعارض فترة الوحدة/الموظف عند التأكيد، وإلغاء الموظف/المطور عن CustomerNoShow (D023–D030).
- للاتفاقات والصفقات: نطاق كل المشاريع أو مشاريع محددة، فترة اتفاق فعالة بلا تداخل للمشروع،
  نسبة من سعر البيع النهائي دون إضافات أو مبلغ ثابت، Project override، Snapshot للصفقة،
  وحماية Lead الافتراضية 90 يومًا قابلة للتعديل أو الصفر (D015–D021).

الرحلات التي تحتاج عقودًا:
قراءة المطورين والمشاريع والوحدات؛ الحساب والجلسة؛
طلبات المعاينة والبدائل والقبول والإلغاء وإعادة الجدولة؛
طلبات الحجز وحالاتها؛ إسناد العملاء ومتابعتهم؛ إدارة المعروض والصفقات والعمولات.

حدود إلزامية:
- عقود العميل لا تحمل ملاحظات المبيعات الداخلية أصلًا.
- إعادة الجدولة تلغي الموعد القديم وفق رد الخادم؛ لا نظهر البديل مؤكدًا قبل التأكيد.
- لا نستنتج تأكيد الحجز من نجاح إرسال الطلب.
- بيانات اختبار أو mock توسم بوضوح ولا تعد نجاح تكامل فعلي.
- تغيير عقد يدوّن هنا وفي قرارات الطرفين قبل اعتماد التنفيذ المتأثر.
المسؤوليات: Backend يثبت العقد والسلوك؛ Frontend يراجع تجربة الحالات وينفذ العقد المتفق عليه.

## حدود القرارات الحالية

- BR-01..BR-16 معتمدة. Q02/D015–D022 وQ03/D023–D030 معتمدتان. أسماء الحالات الإنجليزية في STATE_TRANSITIONS ما زالت Proposed وليست enums نهائية.
- المستخدم اختار دخول العميل بإيميل وكلمة مرور (FE-D008) وفهرسة الكتالوج وتفاصيل الوحدات العامة من أول إصدار (FE-D009). Q01 ما زال Open في نسخة Business المحلية حتى يحدّث المصدر الأساسي ويتزامن؛ التحقق بالبريد والاستعادة ونقل الجلسة وتجديدها وCSRF مفتوحة.
- Q04 توفر البيانات والإخفاء، Q05 ربط العميل التليفوني، Q06 إلغاء الحجز والعربون، Q07 تاريخ الموظف السابق، وصلاحيات Manager/proxy الموسومة P وسياسات الحجز الإضافية تبقى Open/Proposed.
- SC-11 شاشة إدارة موظفين منفصلة كقرار تصميم، لكن بلا UC/FAC معتمد أو مدخل في TRACEABILITY.json. عقدها خارج جرد SC-01..SC-10 الحالي.

### مدخلات ونتائج الأوامر وصلاحياتها — مرشح للمراجعة، لا DTO منفذ

`R` = required في المقترح، `O` = optional أو ينتظر الاتفاق. كل ID معتم؛ `expectedVersion` و`operationKey` حقول نقل مقترحة تحتاج Backend. فاعل الإجراء يستمد من الجلسة، ولا يرسله العميل باعتباره إثبات صلاحية. الاختصارات A/P هي حالة مصفوفة ACTORS، وليست نتيجة تنفيذ. عمليات القراءة ترجع الإسقاط المسموح في الجدول التالي، مع مرشحات اختيارية وحدود paging متفق عليها؛ أي طلب ID خاص يعيد فحص الملكية.

| الإسقاط | حقول مقترحة لازمة للواجهة | مستبعد أو مشروط |

## نتائج Business التي يجب أن يحافظ عليها العقد

- المعاينات Q03/D023–D030: أسماء الحالات الإنجليزية **ليست enums نهائية**. انتهاء pending يُفحص عند commit حتى لو تأخر العامل؛ PendingConfirmation تنتهي عند الأسبق من بداية المقترح أو سبعة أيام من الدورة الحالية، والبديل غير المقبول عند بدايته، وConfirmed لا تنتهي تلقائيًا. أول تأكيد/قبول صحيح لفترة متداخلة للوحدة أو الموظف يفوز؛ الآخر يظل pending لبديل. إلغاء/إعادة جدولة العميل يفحص بداية الموعد، والنتيجة وإلغاء الموظف/المطور يحفظان الفاعل والسبب. `VIEWING_EXPIRED` و`VIEWING_CONFLICT` و`VIEWING_STARTED` أسماء أخطاء مرشحة فقط.
- الحجوزات: إنشاء الطلب ليس تأكيد المطور. التأكيد يحتفظ بالمرجع والسعر والمهلة ولو تغير الإعلان. انتهاء المهلة لا يجعل توفر الوحدة معلومًا. العربون سجل خارجي مستقل لا صفقة. إلغاء Q06، مهلة انتظار الرد، الرد المتأخر، تنافس التأكيدات، التمديد وربط البيع بالحجز ما زالت Proposed/Open؛ أي عملية تعتمد عليها مشروطة.
- الاتفاقات والصفقات Q02/D015–D022: الاتفاق لمطور واحد؛ نطاق كل المشاريع يشمل المستقبلية، والنطاق المحدد لا يفعل. تداخل اتفاقين فعالين على مشروع مرفوض. النسبة على سعر البيع النهائي دون إضافات ورسوم أو قيمة ثابتة؛ Project override يسبق الافتراضي. حماية Lead 90 يومًا افتراضيًا وقابلة للتعديل أو الصفر. Snapshot الصفقة يحفظ القاعدة والأساس والقيمة ولا يتغير بتعديل الاتفاق.
- الإخطارات: فشل إرسال/قراءة الإخطار لا يلغي عملية Business محفوظة ولا يعرضها كأنها فشلت. فتح المورد المرتبط يعيد فحص الملكية/الإسناد.

## عقد الفهرسة العامة FE-D009

اقتراح Angular هو SSR للكتالوج وتفاصيل الوحدة العامة، وCSR للمسارات الخاصة. API القراءة العامة للـSSR يعيد المنشور وحقولًا مجهولة آمنة فقط؛ لا جلسة ولا ملاحظات أو كائن موظف في HTML أو hydration cache. تفاصيل الوحدة تحتاج URL عامًا ثابتًا وردًا صحيحًا عندما تُخفى/تُلغى. فلترة URL وcanonical والروابط القابلة للزحف والmetadata وsitemap والاستضافة بنود قبول F02، وليست ميزات منفذة. SSR يساعد أن يظهر المحتوى في HTML الأولي لكنه **لا يضمن إدراج Google**. المراجع: https://angular.dev/guide/routing/rendering-strategies ؛ https://angular.dev/guide/ssr ؛ https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics ؛ https://developers.google.com/search/docs/crawling-indexing/canonicalization .

## ما يلزم الاتفاق عليه قبل التنفيذ المتأثر

1. يوفر Backend خريطة method/path/schema وإصدارًا قابلًا للاختبار لكل عملية قبل تسمية frontend adapter متكاملًا. نسجل أمثلة نجاح، validation، غياب جلسة، منع، تعارض/انتهاء وtimeout غير معلوم؛ ونحدد متى يستخدم 404 غير كاشف بدل 403.
2. نوائم FE-D008 مع Q01 الأساسي؛ نحسم التحقق والاستعادة ودخول الموظفين ونقل الجلسة قبل SC-03/جلسة F02. نحسم Q04 قبل سلوك قدم التوفر، Q05 قبل ربط العميل التليفوني، Q06 قبل الإلغاء/العربون، Q07 قبل عرض التاريخ للموظف السابق. صلاحيات manager/proxy المقترحة تحتاج اعتمادًا صريحًا.
3. نتأكد من بيئة استضافة SSR وAPI عام آمن وسياسة الفهرسة قبل عمل تصيير F02. نحسم العملة والتوقيت وشكل decimal قبل نماذج المال والوقت.
4. SC-11 تحتاج UC/FAC/trace أساسيًا قبل تنفيذها. اعتماد شكل الشاشة المنفصلة لا يعتمد صلاحياتها.
5. تغير عقد Backend يحدث هنا وفي SC/FAC والدليل المرتبط. mock أو صف وثائق لا يثبت تكاملًا فعليًا.
