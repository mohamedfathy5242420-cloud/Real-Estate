# Screens and flows
أسماء الشاشات وحدودها Proposed للتصميم؛ قواعد BR معتمدة كما في shared.
الحالات المشتركة: تحميل، فارغ، نجاح، خطأ وإعادة محاولة؛ 401/403 وتعارض عند انطباقها.
كل شاشة قابلة للعمل بلوحة المفاتيح والموبايل. اللغة الأولى English LTR معتمدة في FE-D007؛ العربية/RTL لاحقًا ما زالت خيار تصميم.

## SC-01 — الكتالوج العام
Actor: الجميع. UC-02. BR-03, BR-04.
بحث وفلاتر وترتيب وصفحات ثم تفاصيل. حفظ الفلاتر في URL مقترح UX.
فارغ يوضح عدم وجود نتائج؛ الخطأ لا يعرض بيانات قديمة كأنها نتيجة بحث جديدة.
API need: المنشور فقط مع paging/filter metadata. FAC-02.

## SC-02 — تفاصيل الوحدة
Actor: الجميع. UC-02, UC-07. BR-03, BR-04, BR-10, BR-16.
عرض السعر ومصدر/وقت التحديث المناسب للعميل، وطلب معاينة/حجز.
الطلب يحتاج جلسة؛ لا صياغة تضمن حجز الوحدة بمجرد الضغط.
تغير التوفر يعرض رد الخادم ورسالة واضحة، دون بيع أو حجز متفائل. FAC-02, FAC-07.

## SC-03 — الحساب والجلسة
Actor: العميل؛ دخول الموظفين بتفاصيل تحدد لاحقًا. UC-02. BR-04.
اختار المستخدم إيميلًا وكلمة مرور لدخول العميل في FE-D008؛ Q01 في Business ما زال Open لحين تحديث المصدر. الاستعادة والتحقق ونقل الجلسة لم تُحسم. الرجوع للرحلة المطلوبة بعد الدخول مقترح UX.
انتهاء الجلسة يوقف إرسال الطلبات المحمية؛ إعادة الطلب بعد الدخول لا تنفذ mutation مرتين.
API need: auth/session contract؛ لا اختيار تخزين token قبل الاتفاق. FAC-02.

## SC-04 — معاينات العميل
Actor: صاحب الطلب. UC-04, UC-05, UC-06. BR-07, BR-08, BR-09.
إنشاء موعد مقترح → انتظار → قبول بديل/طلب تغييره → حالة نهائية.
إلغاء/تغيير قبل البداية؛ لا ملاحظات داخلية في view model أو payload.
التوقيت يعرض بالمنطقة الزمنية المتفق عليها، والخادم يحسم الحد الزمني.
طبقًا لـD023–D030: الاقتراح خلال 30 يومًا، ومدته الافتراضية 60 دقيقة؛ تخزين الوقت UTC
وعرضه بتوقيت المشروع/المستخدم. PendingConfirmation ينتهي بعد سبعة أيام أو المقترح أيهما أقرب،
والبديل عند وقته؛ Confirmed لا ينتهي لمجرد مرور الوقت. الفترة تُحجز عند التأكيد فقط.
تغييرات متزامنة: تحديث الحالة عند التعارض، لا نجاح وهمي. FAC-04, FAC-05, FAC-06.

## SC-05 — متابعة معاينات الموظف
Actor: الموظف المسؤول والمدير وفق الصلاحيات. UC-04, UC-05, UC-06.
قراءة الطلب → تسجيل التنسيق الخارجي → تأكيد أو بديل → نتيجة وملاحظات.
حقول الملاحظات منفصلة عن الرسائل المرئية للعميل.
النقل/سحب الصلاحية أثناء فتح الصفحة يوقف التعديل عند رفض الخادم. FAC-04, FAC-05, FAC-06.
عند تأكيد فترتين متداخلتين لنفس الوحدة أو الموظف يفوز أول تأكيد صحيح، والآخر يبقى Pending.
إلغاء الموظف أو عدم توفر المطور Cancelled بسبب وفاعل، وليس CustomerNoShow (D026، D029).

## SC-06 — العملاء والإسناد
Actor: المدير للإسناد، والموظف للعملاء المسندين. UC-03. BR-05, BR-06, BR-15.
قائمة غير مسندين → اختيار موظف → عرض المسؤول والسجل → نقل عبر المدير.
لا auto-distribution جديد. تفاصيل وصول الموظف السابق Q07.
API need: customer assignment, history, server-filtered lists. FAC-03.

## SC-07 — إدارة المعروض والاتفاقات
Actor: الإدارة حسب المصفوفة. UC-01. BR-01, BR-02, BR-03, BR-14, BR-15.
مطور → مشروع → وحدة واتفاق؛ تحرير ونشر وتحديث السعر/التوفر.
النشر والتوفر حقول منفصلة؛ تكرار الكود يعرض خطأ الحقل الوارد من الخادم.
لا حساب للمطور أو دفع عمولة آلي. FAC-01.
تحديث D015–D021: Q02 حُسم لنطاق الاتفاق والعمولة؛ الاتفاق لمطور واحد ويغطي كل مشاريعه
أو مشاريع محددة، وتُمنع فترات التغطية الفعالة المتداخلة للمشروع. النسبة أو المبلغ الثابت،
Project override، وحماية Lead تفاصيل معتمدة؛ عقد حقولها النهائي في F01-S04.

## SC-08 — الحجوزات
Actor: العميل يرى طلباته؛ الموظف يسجل رد المطور؛ المدير حسب الصلاحيات.
UC-07, UC-08. BR-10, BR-11, BR-12, BR-13, BR-16.
تقديم → انتظار مراجعة → رد خارجي مسجل → حالة ومهلة.
حقول تسجيل التأكيد للموظف، وعرض الحالة للعميل؛ العقد النهائي يحسم الحقول المسموح عرضها.
انتهاء المهلة لا يفعّل زر حجز على أساس توفر افتراضي. العربون منفصل عن الصفقة والعمولة.
فشل/timeout الإرسال: استعلام الحالة أو آلية idempotency متفق عليها، لا إعادة عمياء. FAC-07, FAC-08.

## SC-09 — الصفقات والعمولات
Actor: مدير المبيعات. UC-09. BR-13, BR-14, BR-15.
عرض واعتماد الصفقة، لقطة العمولة، تسجيل التحصيل وفق D015–D021.
وفق D016–D021: النسبة من سعر البيع النهائي دون الرسوم والإضافات أو مبلغ ثابت،
Project override يسبق القاعدة الافتراضية، والصفقة تحفظ القاعدة والسعر والقيمة.
حماية Lead الافتراضية 90 يومًا قابلة للتعديل أو الصفر، مع تحقق الخادم من سريان الاتفاق.
لا يعاد حساب الصفقة القديمة من اتفاق اليوم في المتصفح.
API need: snapshot ومعلومات التحصيل والتعارض. FAC-09.

## SC-10 — الإشعارات وسجل الحالة
Actor: المستلم المسموح. UC-10. BR-08, BR-15.
عرض تحديثات تخص المستخدم والانتقال للمورد مع فحص الصلاحية.
قناة الإشعار وطريقة التحديث غير محسومتين؛ الإشعار لا يصبح مصدر حقيقة للحجز.
رفض الوصول للرابط بعد نقل المسؤولية يعرض حالة مناسبة دون كشف بيانات. FAC-10.

## Open UI design
المسارات والـlayout مقترحة في F01-S01/S02؛ لم تعتمد مكتبة UI أو endpoints فعلية. هذه مخرجات F01-S04 للمراجعة.
الحالات الأساسية أعلاه معيار تصميم، وليست إثبات صفحات مبنية أو اختبار متصفح.
