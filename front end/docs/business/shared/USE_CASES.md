# Use cases

هذه رحلات Business؛ تفاصيل Open لا تتحول إلى قواعد تنفيذ.
كل UC يربط الفاعل والشروط والخطوات والنتيجة والفشل بالقواعد ومعايير القبول.

## UC-01 — إدارة المعروض
Actor: الإدارة.
Preconditions: صلاحية إدارة؛ وجود المطور قبل المشروع والمشروع قبل الوحدة.
Flow: تسجيل المطور والمشروع → اتفاق تسويق → الوحدة وبيانات السعر والتوفر → نشر وفق النطاق.
Result: وحدة معرفة ويمكن قراءة المنشور منها.
Failure: كود مكرر داخل المشروع، مرجع غير موجود، اتفاق غير صالح أو متداخل على المشروع.
Rules: BR-01, BR-02, BR-03, BR-14, BR-15.
Acceptance: AC-01, AC-02. Phase: P03.

## UC-02 — البحث وبدء الطلب
Actor: زائر ثم عميل.
Preconditions: وحدة منشورة.
Flow: بحث وقراءة تفاصيل → طلب معاينة/حجز → تسجيل الدخول إن لم توجد جلسة.
Result: طلب مرتبط بصاحبه، لا حجز مؤكد.
Failure: وحدة غير منشورة؛ جلسة غائبة؛ محاولة الوصول لطلب شخص آخر.
Rules: BR-03, BR-04, BR-10.
Acceptance: AC-03, AC-04. Phases: P02, P03.

## UC-03 — إسناد ومتابعة العميل
Actor: المدير والموظف.
Preconditions: عميل صاحب طلب.
Flow: غير مسند → المدير يختار الموظف → الطلبات التالية لنفس الموظف →
نقل عند الحاجة مع تاريخ وفاعل.
Result: مسؤول واضح للعميل وطلباته.
Failure: موظف خارج النطاق يحاول قراءة الطلب؛ سياسة الموظف السابق Q07.
Rules: BR-05, BR-06, BR-15.
Acceptance: AC-05. Phase: P04.

## UC-04 — ترتيب معاينة
Actor: العميل والموظف.
Preconditions: حساب العميل؛ الإسناد قبل تدخل موظف.
Flow: العميل يقترح وقتًا → الموظف ينسق خارجيًا → يؤكد المطلوب، أو يقترح بديلًا →
العميل يقبل البديل ليؤكد، أو يطلب تعديلًا.
Result: موعد مؤكد فقط عند اكتمال الدورة.
Failure: وقت أبعد من 30 يومًا؛ انتهاء pending؛ تعارض وحدة/موظف عند التأكيد يبقي الطلب pending لبديل.
Rules: BR-04, BR-07.
Acceptance: AC-06. Phase: P05.

## UC-05 — إلغاء/إعادة جدولة
Actor: العميل صاحب المعاينة.
Preconditions: قبل موعد البداية؛ الطلب قابل للتعديل.
Flow: إلغاء يخطر الموظف؛ أو طلب تغيير يلغي القديم فورًا ويحفظ تاريخه →
انتظار دورة تأكيد جديدة.
Result: لا يظل الموعد القديم مؤكدًا؛ الجديد ليس مؤكدًا تلقائيًا.
Failure: طلب بعد بداية الموعد يرفض وفق قاعدة الزمن؛ معالجة موظف لحالة استثنائية Open.
Rules: BR-08, BR-15.
Acceptance: AC-07, AC-08. Phase: P05.

## UC-06 — نتيجة المعاينة
Actor: الموظف المسؤول.
Preconditions: معاينة مؤكد حدوث موعدها؛ ضبط توقيت إغلاق النتيجة تفصيل تصميم.
Flow: يسجل تمت أو لم يحضر العميل → ملاحظات المتابعة الداخلية.
Result: العميل يرى النتيجة دون الملاحظات.
Failure: موظف غير مسؤول؛ لا يصنف غياب المطور/إلغاء الموظف كغياب العميل بل Cancelled بسبب مسجل.
Rules: BR-06, BR-09, BR-15.
Acceptance: AC-09. Phase: P05.

## UC-07 — طلب وتأكيد الحجز
Actor: العميل والموظف.
Preconditions: حساب العميل؛ لا اشتراط معاينة.
Flow: تقديم الطلب → مراجعة الموظف للتوفر والسعر خارجيًا →
تسجيل رفض أو تأكيد المطور ومرجعه وسعره ومهلته.
Result: طلب أو تأكيد خارجي موثق، لا بيع مكتمل.
Failure: رفض المطور، تغير السعر/التوفر، طلب مكرر؛ تفصيل التزامن في S03.
Rules: BR-04, BR-10, BR-11, BR-16.
Acceptance: AC-10, AC-11. Phase: P06.

## UC-08 — انتهاء/إلغاء حجز وعربون
Actor: موظف/مدير؛ المعالجة الزمنية التقنية تحدد لاحقًا.
Preconditions: حجز بشروط المطور.
Flow: تسجيل دفع العربون الخارجي عند تأكيده؛ عند انتهاء المهلة يسجل الانتهاء →
يعاد التحقق من توفر الوحدة. الإلغاء بعد التأكيد يتبع Q06.
Result: لا إتاحة تلقائية للوحدة ولا خلط العربون بعمولة.
Failure: رد خارجي متأخر أو إلغاء متزامن؛ لا نفترض استرجاعًا آليًا.
Rules: BR-11, BR-12, BR-13, BR-16.
Acceptance: AC-12. Phase: P06.

## UC-09 — الصفقة والعمولة
Actor: مدير المبيعات.
Preconditions: تأكيد بيع خارجي موثق واتفاق تسويق.
Flow: اعتماد الصفقة بسعر البيع → حفظ قاعدة العمولة وقيمتها →
تسجيل الاستحقاق والتحصيل.
Result: لقطة مالية تاريخية لا تتبدل بتعديل الاتفاق.
Failure: قاعدة عمولة غير محددة، اتفاق غير منطبق/انتهاء الحماية، أو محاولة تحصيل مكرر.
Rules: BR-13, BR-14, BR-15.
Acceptance: AC-13. Phase: P07.

## UC-10 — الإخطار والتتبع
Actor: النظام، والمستلم صاحب الحدث.
Preconditions: تغيير معتمد يستدعي إخطارًا.
Flow: حفظ العملية وتاريخها → تجهيز إخطار → إرساله مع محاولات لاحقة عند الفشل.
Result: لا يفقد الحدث الأساسي بسبب تعطل قناة الإخطار.
Failure: تكرار/فشل إرسال؛ حفظ دائم ومنع تكرار الأثر تفاصيل تقنية مقترحة.
Rules: BR-08, BR-15.
Acceptance: AC-14. Phase: P08.
