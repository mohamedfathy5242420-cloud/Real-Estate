# Acceptance scenarios
حالات قبول لتصميم الاختبارات لاحقًا، وليست نتائج اختبارات ناجحة.

## AC-01 — تعريف الوحدة
Given مشروع ووحدة كودها A1، When إضافة A1 لنفس المشروع، Then ترفض.
نفس الكود في مشروع آخر مسموح. Rules: BR-02.
Given اتفاقان فعالان يغطيان المشروع نفسه في فترة متداخلة، When تفعيل الثاني، Then يرفض.
Given اتفاقًا عامًا، Then مشروع المطور الجديد يدخل نطاقه؛ والاتفاق المحدد لا يغطيه تلقائيًا. Rules: BR-14.

## AC-02 — المعروض والتأكيد
Given وحدة غير منشورة، When زائر يطلبها، Then لا تظهر بياناتها العامة.
Given تعديل السعر والتوفر، Then يسجل مصدر ووقت التأكيد ويظل النشر مستقلًا.
Rules: BR-03, BR-15.

## AC-03 — تصفح بلا حساب
Given زائر، When يبحث عن وحدة منشورة، Then يرى تفاصيلها وأسعارها دون تسجيل.
Rules: BR-04.

## AC-04 — ملكية الطلب
Given طلب عميل أ، When عميل ب يحاول قراءته/تغييره، Then لا يحصل على البيانات ولا ينفذ التغيير.
Given زائر، When يقدم طلبًا، Then يلزم تسجيل الدخول. Rules: BR-04, BR-06.

## AC-05 — الإسناد
Given عميل غير مسند، Then ينتظر تعيين المدير.
Given موظف مسؤول، When العميل يطلب وحدة أخرى، Then نفس المسؤول يتابع الطلب.
When المدير ينقل المسؤولية، Then يحفظ القديم والجديد والفاعل والوقت. Rules: BR-05, BR-06, BR-15.

## AC-06 — البديل يحتاج قبولًا
Given موعد غير متاح، When الموظف يقدم بديلًا منسقًا، Then يظل غير مؤكد
حتى يقبله العميل. Rules: BR-07.
Given طلبين متداخلين، When يتأكد الأول، Then حجز الفترة؛ ومحاولة تأكيد الثاني تتعارض
وتتركه Pending لبديل. يمنع التداخل لنفس الوحدة أو الموظف.

## AC-07 — تغيير موعد مؤكد
Given معاينة مؤكدة لم تبدأ، When العميل يطلب تغييرًا،
Then يلغي القديم فورًا ويحفظ التاريخ ويخطر الموظف، والجديد ينتظر التأكيد.
Rules: BR-08, BR-15.

## AC-08 — حد الإلغاء
Given موعد لم يبدأ، When العميل يلغي، Then يتوقف الموعد ويخطر الموظف.
Given بدأت المعاينة، Then لا يسمح بنفس إجراء الإلغاء الذاتي السابق للبداية.
Given PendingConfirmation، Then ينتهي عند سبعة أيام أو الموعد المقترح أيهما أقرب.
Given معاينة Confirmed مر وقتها، Then لا تتحول Expired؛ تنتظر تسجيل النتيجة.
Rules: BR-08.

## AC-09 — الملاحظات خاصة
Given نتيجة وملاحظات موظف، When العميل يقرأ طلبه، Then يرى الحالة ولا توجد الملاحظات في payload.
When موظف خارج الإسناد يطلبها، Then يمنع الوصول. Rules: BR-06, BR-09.
Given غياب المطور أو إلغاء الموظف، Then تسجل Cancelled بالفاعل والسبب، ولا تسجل CustomerNoShow.

## AC-10 — الطلب ليس تأكيدًا
Given عميل دون معاينة، When يقدم طلب حجز، Then يقبل كطلب مراجعة فقط.
لا يؤدي توفر Cache أو الطلب المحلي لتأكيد خارجي. Rules: BR-10, BR-16.

## AC-11 — سعر التأكيد
Given رد مطور مؤكد، When يسجله الموظف، Then يحفظ المرجع والسعر والمهلة.
When سعر الإعلان يتغير، Then سعر الحجز المحفوظ لا يتغير. Rules: BR-11.

## AC-12 — انتهاء وعربون
Given حجز تنتهي مهلته، When يسجل الانتهاء، Then لا تعود الوحدة متاحة تلقائيًا.
Given تسجيل عربون خارجي، Then لا يصبح بيعًا مكتملًا أو عمولة. Rules: BR-12, BR-13.

## AC-13 — عمولة تاريخية
Given صفقة معتمدة وعمولة محفوظة، When تعدل قاعدة الاتفاق،
Then لا تتغير عمولة الصفقة القديمة.
Given قاعدة نسبة، Then تحسب على سعر بيع الوحدة النهائي دون الرسوم والإضافات.
Given Project override، Then يسبق القاعدة الافتراضية.
Given Lead فتحت أثناء الاتفاق والبيع داخل مدة الحماية، Then يظل الاتفاق مؤهلًا.
Rules: BR-14.

## AC-14 — تعطل الإخطار
Given تغيير محفوظ يستدعي إخطارًا، When تفشل القناة، Then العملية الأساسية باقية.
تفاصيل إعادة المحاولة ومنع الأثر المكرر جزء من تصميم P08. Rules: BR-08, BR-15.
