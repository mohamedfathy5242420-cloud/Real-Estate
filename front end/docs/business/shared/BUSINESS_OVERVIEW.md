# Business overview

## لماذا يوجد المنتج؟
شركة وساطة تعرض وحدات مطورين متعددين، وتدير متابعة العميل من اهتمامه حتى البيع،
ثم تسجل العمولة المستحقة لها وتحصيلها. ليست الشركة مالكة المخزون ولا نظام المطور الداخلي.

## الأطراف
العميل يطلب؛ موظف البروكر يتابع؛ المدير يسند ويتابع الصفقات؛ الإدارة تدير المعروض.
المطور طرف خارجي يملك حقيقة التوفر ويؤكد الحجز خارج النظام.
الزائر يقرأ المعروض قبل إنشاء حساب.

## المصطلحات
| المصطلح | المعنى |
| --- | --- |
| Developer | شركة تطوير عقاري، لا مستخدم للنظام في النسخة الأولى |
| Project | مشروع عقاري تابع لمطور واحد |
| Unit | وحدة بيع تابعة لمشروع؛ موضوع التسعير والحجز |
| MarketingAgreement | اتفاق تسويق ونطاقه ومدته وقاعدة عمولته |
| Customer | الشخص الذي تتم متابعته؛ تفاصيل ربط عميل تليفوني بحساب ما زالت Q05 |
| Lead | فرصة/احتياج بيع للعميل؛ ليست حسابًا أو حجزًا |
| Assignment | الموظف المسؤول عن العميل، لا توزيع مستقل تلقائي لكل طلب |
| Viewing | طلب معاينة، الموعد المقترح يختلف عن المؤكد |
| ReservationRequest | رغبة في الحجز وليست إثبات توفر أو بيع |
| Confirmed reservation | حجز أكده المطور مع مرجع وسعر ومهلة |
| Deal | بيع مكتمل سجل واعتمد وفق صلاحياته |
| Commission | استحقاق البروكر، منفصل عن عربون العميل |

## الرحلة
تسجيل المطور والمشروع والاتفاق والوحدة → نشر وبحث → حساب وطلب →
إسناد ومتابعة → معاينة اختيارية → طلب حجز → تأكيد المطور الخارجي → صفقة وعمولة.
إلغاء أو رفض أو تغير توفر ممكن خلال الرحلة؛ لا نجاح ضمني لمجرد تقديم طلب.

## الحدود
بيع فقط، بروكر واحد، مطورون متعددون. دفع العربون خارج النظام وتأكيده يسجل داخله.
لا بوابة مطور أو Multi-tenancy أو أقساط أو دفع حقيقي أو عقود قانونية في النسخة الأولى.
التفاصيل الدقيقة للنطاق في ../MVP_SCOPE.md.
